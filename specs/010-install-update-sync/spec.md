# 010 Install, update and sync

## Context

`install` puts the kit into a repository: a private copy of the core in `.agentkit/`, the
config, AGENTS.md, skills, git hooks, CI and the chosen adapters. `update` brings a newer kit
version without overwriting files the user customised. `sync` regenerates per-tool copies of
skills and roles from the repo's neutral sources, and `sync --check` fails CI on drift.

## File modes

| Mode | Written when | Examples |
|---|---|---|
| once | only if missing | `agentkit.toml`, the lock, the unfreeze log, `specs/README.md` |
| managed | 3-way rule (R010-12) | kit skills in `.agents/skills/`, `.githooks/*`, CI files, adapter config |
| block | only the region between agentkit markers | `AGENTS.md`, `CLAUDE.md`, `.gitignore`, `CODEOWNERS` |
| derived | always regenerated by `sync`, drift-checked | `.claude/skills/*`, `.claude/agents/*`, `.codex/agents/*`, `.opencode/agents/*` |

## Requirements (EARS)

### install
- **R010-01** `agentkit install --target DIR [--profile P] [--adapters a,b] [--ci PROVIDERS] [--ci-os OSES] [--models tool|kit] [--owner @x] [--python CMD] [--force] [--self]`
  shall install into DIR. DIR must exist. PROVIDERS is `none` or a comma list of `github` and
  `gitlab`. OSES is a comma list of `linux`, `windows` and `macos`.
- **R010-02** If an adapter, profile or CI value is unknown, then install shall exit 2 and write
  nothing. The known adapters are `claude-code`, `codex`, `opencode`, `deepseek-harness` and `pi`.
- **R010-03** When `agentkit.toml` is missing, install shall render it from the template with
  the given options, storing `--ci` and `--ci-os` in the `[ci]` table. Defaults: profile
  `generic`, python per R001-07.
- **R010-23** When `agentkit.toml` is missing, install shall require `--ci` to be given. When
  `--ci` is not `none`, it shall also require `--ci-os`. If either is missing, install writes
  nothing and exits 2, explaining both options. The operating systems are the project owner's
  choice; there is no silent default.
- **R010-25** When `agentkit.toml` is missing, install shall require `--models tool|kit`
  (R001-17 to R001-19). If it is missing, install writes nothing and exits 2, explaining both
  modes. When the config exists, `--models` replaces the stored mode.
- **R010-24** When `agentkit.toml` exists, `--ci` and `--ci-os` shall replace the stored values.
  Otherwise the stored values are kept.
- **R010-04** When `agentkit.toml` exists, install shall keep it, except that newly given
  adapters are added to `[kit] adapters`, and R010-24 applies.
- **R010-05** When the `deepseek-harness` adapter is selected, install shall also select `codex`.
- **R010-06** Unless self-hosted, install shall replace `.agentkit/{agentkit,profiles,workflow,skills,adapters,githooks,ci}`
  with copies from the kit (without `__pycache__`), and write `.agentkit/README.md`
  ("installed copy, do not edit").
- **R010-07** install shall write the launchers `.agentkit/bin/agentkit` (a Python script with a
  `python3` shebang, executable) and `.agentkit/bin/agentkit.cmd`. The launcher puts the package
  directory (`.agentkit/` or, when self-hosted, the root) on `sys.path`, sets `AGENTKIT_ROOT`
  to the root, and runs `agentkit.cli.main`.
- **R010-08** install shall write the files planned by the kit (this spec, plus 011, 012 to 016
  and 018) using their modes, then run sync.
- **R010-09** Where DIR is a git repository, install shall set `git config core.hooksPath .githooks`.
  Otherwise it prints a note on how to do so.
- **R010-10** When `--owner` is given, install shall maintain a block in `.github/CODEOWNERS` that
  assigns the owner to the lock, the unfreeze log, `.agentkit/`, `.githooks/`, every frozen glob,
  the chaos log (`[chaos] log`, default `chaos-log.jsonl`) and `<paths.specs>/*/reviews/` (020).
- **R010-11** install shall maintain a `.gitignore` block with `.agentkit/state/`, `__pycache__/`,
  `*.agentkit-new` and `.autopilot/` (021).

### Managed files (3-way)
- **R010-12** For a managed file, let `new` be the kit's rendered content, `base` the hash
  recorded in the manifest, and `cur` the hash of the file on disk. Then:

  | Situation | Result |
  |---|---|
  | `cur == new` | unchanged |
  | file missing, never installed | write |
  | file missing, was installed (user deleted it) | skip and report, unless `--force` |
  | `cur == base` (not customised) | overwrite |
  | `cur != base`, or not in manifest | write `<file>.agentkit-new`, report a conflict, unless `--force` |
- **R010-13** Executable managed files (git hooks) shall get the executable bit.

### Blocks
- **R010-14** A block file shall use the markers
  `<!-- agentkit:begin (managed by agentkit; edit outside this block) -->` and
  `<!-- agentkit:end -->` for Markdown, and `# agentkit:begin …` / `# agentkit:end …` for
  `.gitignore` and CODEOWNERS.
- **R010-15** When the file is missing, the whole template shall be written. When it has the
  markers, only the region between them is replaced. When it exists without markers, the block
  is added at the end (at the top for `CLAUDE.md`).

### Manifest
- **R010-16** `.agentkit/manifest.json` shall record the kit version and, for each managed,
  block and derived file, its hash and mode.

### update and sync
- **R010-17** `agentkit update [--kit PATH] [--force]` shall re-run install with the existing
  config and the kit at PATH (default: the installed copy). It exits 1 when there are conflicts.
- **R010-18** `agentkit sync` shall regenerate every derived file of the configured adapters
  from `<paths.skills>`, the kit roles and the project roles (`<paths.roles>`).
- **R010-19** sync shall delete a derived file recorded in the manifest that is no longer
  produced, if it is unchanged since it was generated, and remove the empty directories left.
- **R010-20** `agentkit sync --check` shall write nothing. It lists every derived file that is
  missing, different or stale, and exits 1 if there is any.
- **R010-21** Running install twice with the same inputs shall write no file the second time.
- **R010-22** install shall print a summary of written, conflicting, skipped and removed files,
  plus each adapter's post-install notes (for example Codex's `/hooks` trust step).

## Public API contract

```text
agentkit/install.py:
  @dataclass Planned(path, content: bytes, mode, initial=None, markers=..., placement="bottom", executable=False)
  @dataclass Report(written, unchanged, conflicts, skipped, removed, drift, notes); lines()
  render(text, ctx) -> str          # replaces {{key}} for known keys only
  plan_kit(cfg, src, ci, owner) -> list[Planned]
  plan_derived(cfg) -> list[Planned]
  apply(root, planned, manifest, force=False, check=False, derived_scope=False) -> Report
  install(target, profile=None, adapters=None, ci=None, owner="", python=None, src=KIT_ROOT,
          force=False, self_hosted=False) -> Report
  update(root, src, force=False) -> Report
  sync(cfg, check=False) -> Report
agentkit/adapters.py: kit_files(name, cfg, src, ctx), derived_files(name, cfg, ctx), post_install_notes(name)
```

## Examples and edge cases

- A user edits `.githooks/pre-commit`, then runs `update`: the file is kept,
  `.githooks/pre-commit.agentkit-new` is written, and the exit code is 1.
- `render` must leave GitHub's `${{ github.base_ref }}` untouched (unknown key, spaces).
- A skill is deleted from `.agents/skills/`: sync removes `.claude/skills/<it>/` if it is unchanged.
